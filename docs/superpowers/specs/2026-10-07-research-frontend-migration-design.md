## 功能完整性

1. 复用控制台公司列表、创建和公司切换，保持公司级任务与报告隔离。
2. 投研部门安装、安装中/失败/就绪状态、安装重试、公司启动失败重试以及容器操作状态。
3. A 股和美股能力判定、股票代码校验与规范化、研究深度限制、语言能力限制、幂等提交及提交失败后使用相同请求编号重试。
4. 任务列表、状态和市场筛选、三阶段执行进度、开始/结束时间、错误原因、报告覆盖度和缺失数据提示。
5. 重新研究、继续研究和取消任务，按任务及运行状态限制可执行动作。
6. 当前公司及单项任务的 HTML 成果、历史版本、每次 200 条继续加载、签名预览链接和下载。
7. 完整投资流派和人物目录、流派筛选、可对话与仅研究评审人物的区别；保持英语目录的原有地区过滤行为。
8. 读取服务端可用人物及能力、创建一般对话或报告绑定对话、切换历史会话、持续读取生成进度和回复。
9. 圆桌讨论保留原有参与人数/发言顺序限制、流派筛选、能力限制、角色选择草稿、报告绑定、逐人发言和状态展示。
10. 回复引用与报告关联、截断/引用不可核验/历史上下文覆盖提示；人物模拟免责声明及输入上限。
11. 中文和英文的全部现有界面文案、人物展示名及日期格式；用户输入、报告和生成内容不自动翻译。

## 页面和模块组织

- 在现有公司工作空间增加“投研”侧栏入口，使用 HashRouter 路由 `/console/#/business/c/:companyId/research`。
- 页面在 `console/src/pages/business/company/` 内组织，使用现有 `CompanyShell`、公司上下文、登录保护、语言切换和通知机制。
- 研究提交、部门状态、任务列表/详情、成果列表、人物目录和对话/圆桌拆成具有独立职责的 React 组件；按研究、成果和人物讨论分区，移动端采用纵向排列。
- 可独立测试的股票校验、能力过滤、幂等键、运行阶段、目录数据、对话上下文校验和引用校验放入 `console/src/lib/research/`；保留可运行的纯逻辑，并为 TypeScript 提供准确类型。
- 用 React 状态和组件卸载清理替换全局 DOM 事件、全局文档扫描和不可回收的定时器。React StrictMode 下不重复发起写请求，不泄漏订阅。
- 创建公司沿用既有页面入口，不另建重复表单；创建后可通过公司导航进入投研页。

## 视觉与交互规范

- 沿用 `tailwind.config.ts` 和控制台现有色彩：背景 `#07090F`、面板 `#0D1119`、主色 `#D4A84E`、标题 `#E8DCC8`。
- 字体沿用 Instrument Serif、Barlow、Share Tech Mono；状态色沿用已有 mint/blue/flare/fusion。
- 沿用现有间距、按钮、输入框、边框、圆角、通知、加载和空状态。原工作台浅色 CSS 不作为全局样式引入。
- 任务详情与成果信息保持信息密度和阅读顺序；对话可清楚区分用户、人物发言、状态、引用和错误。
- 表单有可访问标签；状态反馈通过 live region；键盘可操作人物选择、任务动作和圆桌参与者；尊重 reduced-motion。
- 不扩展原来没有的阿拉伯语投研内容。控制台选择阿拉伯语时，投研文案和研究请求回退英语，并清楚使用一致的布局方向。

## 接口与运行约束

- 保留既有 `/v1/companies/...` 研究、任务、部门、对话、操作和成果接口，不修改后端 API。
- 复用 `console/src/lib/api.ts` 的 API 基址和 cookie。为研究操作保留 `Idempotency-Key` 请求头与请求超时；必要时扩展该包装器的可选请求参数，不破坏现有调用。
- 所有公司、任务、运行和会话 ID 编码后进入 URL。签名成果 URL 以 API 主机为基准解析、限制允许的来源及 `/v1/outputs/s/` 路径，与现有成果预览策略保持一致。
- 只读取当前公司数据；公司切换、任务选择、会话切换和组件卸载后，过期响应不能覆盖新上下文。
- 保持原有 5 秒后台状态轮询和对话生成轮询节奏；页面隐藏时暂停不必要请求，离开页面时取消轮询。
- 开发环境使用显式 `VITE_API_TARGET` 指向本地 API `http://127.0.0.1:8002`；不改变生产 API 默认值，不保存登录凭据。
- 验证过程不自动创建公司、安装部门、提交研究、发送对话或取消真实任务。写接口通过受控测试响应验证。
